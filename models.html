Choose a model

Balance capability, thinking effort, and cost against the work in front of you.

Three controls: model, effort, and speed

Model = the engine

The model determines the underlying capabilities. A faster, cheaper model may be enough for a narrow edit; a more capable model may help with ambiguous problems.

Effort = room to think

Reasoning effort controls how much reasoning the model can use. Higher effort can improve difficult answers, but usually costs time and tokens. It is not a guarantee of correctness.

Speed = a service tier, not extra intelligence

Fast is a separate control from model and reasoning effort. Where available, Fast supports Luna, Sol, and Astra. It uses 2.5× included subscription usage, or 2× purchased credits / pay-as-you-go usage, versus Standard. Those are usage multipliers, not a promise of 2× or 2.5× speed. It does not guarantee faster tools or image generation.

Speed guide
Model ≠ product

Codex and Claude Code are agent products. GPT and Claude are model families. Product tools, prompts, context, permissions, and model routing all affect the result. An API benchmark is not an end-to-end product ranking.

Keep API prices separate from plan usage

API pricing is a rate per token. A ChatGPT or Claude subscription has its own usage rules and limits. Do not multiply this table by your subscription messages. In Codex, inspect your plan’s usage view. In Claude Code, /usage session dollars are API-equivalent estimates, not Pro/Max subscription billing; subscribers should inspect their plan-usage bars.

A practical starting strategy

Choose from the models actually available in your picker. In Claude Code, /effort changes effort; model aliases and supported options can vary by client version and provider.

The following is a course recommendation, not a benchmark result.

Small, easily reviewed work

Start with a fast, lower-cost model or low effort. Examples: rename a variable, reformat a paragraph, or extract fields you can check. Define the exact scope.

A real feature or multi-step analysis

Start with a capable general-purpose model at medium effort. For example, GPT-6.1 Sol medium. In Claude Code, Sonnet 5.5 medium is another practical starting point. Supply relevant files and acceptance tests before escalating.

Repeated failures or a hard reasoning problem

First check missing context and unclear instructions. Then try higher effort or a stronger model. For architecture or multi-file uncertainty, compare Sol xhigh or Astra medium; in Claude Code, consider Opus 5.5 medium/high. Compare outcomes on the same task, not answer length.

What diminishing returns looks like

For Sol on this benchmark, low → medium moves 42 → 48 and $0.13 → $0.21 per task. Medium → max moves 48 → 52 while cost rises to $0.72. More effort has a measurable trade-off; it should earn its place.

Try it · 1 minute

You need one button label changed. Do you start at max effort?

Compare your answer

Usually no. Use a narrow instruction and an inexpensive starting configuration, then check the label and surrounding layout. Spend more reasoning on uncertainty, not automatically on every task.

Run a small comparison on your own task

  1. Use the same task, files, and acceptance criteria.
  2. Try two model/effort configurations.
  3. Record correctness, retries, elapsed time, and usage.
  4. Keep the least costly configuration that reliably passes.

Do not assume the smaller model is always cheaper: Opus medium scores 51 at $1.34 per benchmark task, while Sonnet xhigh scores 52 at $2.74. Token rate alone does not determine total task cost.
