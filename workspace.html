Organize your work

Keep related chats together, give each task a clear goal, and keep parallel code changes separate.

Five terms, one event website

Imagine you are building a small event website. Keep its chats in a Project and its files in a folder. If two agents need to change the code independently, give them separate worktrees.

Project

A ChatGPT Project keeps related chats, instructions, and sources together. A local project connects work to folders on your computer.

Chat

One conversation about an outcome. Keep a debugging investigation together; start a separate chat for the next independent feature.

Folder

A location containing actual files. A chat is not a folder, and creating a ChatGPT project does not automatically grant access to a local folder.

Repository

A folder tracked with Git: files plus version history. A remote such as GitHub hosts a copy you can synchronize and collaborate on.

Worktree

A separate working copy of a Git repository. It has its own files but shares the repository’s history, so two tasks can work without editing the same copy.

One project, several focused conversations

Example · a small event website

Keep the event context together. Split distinct outcomes.

  • Project: the event website, with its brief and shared instructions
  • Chat A: agree the page structure and copy
  • Chat B: implement the registration form
  • Chat C: investigate a mobile layout bug
  • Repository: the website files and their Git history
  • Worktree: an isolated place to try the form while the main checkout stays usable
A new chat is not a fresh filesystem

Two chats can still work in the same folder. If both edit the same files, their changes can interfere. Use separate worktrees when you need isolation; still review and test before combining changes.

When should you start a new chat?

Continue the current chat when…

  • You are refining the same output
  • A test failure belongs to the current change
  • The decisions above are still relevant

Start a new chat when…

  • The desired outcome is different
  • The old discussion adds distracting assumptions
  • You need an independent review or parallel task

Give the new chat a short starting brief: the goal, relevant files, decisions, current result, and next check. Do not assume it has every earlier conversation.

Example handoff

“In the event website project, fix the registration form’s mobile layout. Keep the current desktop design. Relevant file: registration.html. Success means no horizontal scrolling at phone widths and a usable submit button. Explain what you changed and how you checked it.”
